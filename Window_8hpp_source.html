45/**
46 DGL Window class.
47
48 This is the where all OS-related events initially happen, before being propagated to any widgets.
49
50 A Window MUST have an Application instance tied to it.
51 It is not possible to swap Application instances from within the lifetime of a Window.
52 But it is possible to completely change the Widgets that a Window contains during its lifetime.
53
54 Typically the event handling functions as following:
55 Application -> Window -> Top-Level-Widget -> SubWidgets
56
57 Please note that, unlike many other graphical toolkits out there,
58 DGL makes a clear distinction between a Window and a Widget.
59 You cannot directly draw in a Window, you need to create a Widget for that.
60
61 Also, a Window MUST have a single top-level Widget.
62 The Window will take care of global screen positioning and resizing, everything else is sent for widgets to handle.
63
64 ...
65 */

71 /**
72 Window graphics context as a scoped struct.
73 This class gives graphics context drawing time to a window's widgets.
74 Typically used for allowing OpenGL drawing operations during a window + widget constructor.
75
76 Unless you are subclassing the Window or StandaloneWindow classes, you do not need to care.
77 In such cases you will need to use this struct as a way to get a valid OpenGL context.
78 For example in a standalone application:
79 ```
80 int main()
81 {
82 Application app;
83 Window win(app);
84 ScopedPointer<MyCustomTopLevelWidget> widget;
85 {
86 const Window::ScopedGraphicsContext sgc(win);
87 widget = new MyCustomTopLevelWidget(win);
88 }
89 app.exec();
90 return 0;
91 }
92 ```
93
94 This struct is necessary because we cannot automatically make the window leave the OpenGL context in custom code.
95 And we must always cleanly enter and leave the OpenGL context.
96 So in order to avoid messing up the global host context, this class is used around widget creation.
97 */
98 struct ScopedGraphicsContext
99 {
100 /** Constructor that will make the @a window graphics context the current one.
101 If it already is, it is left current when done, so scopes can nest. */
102 explicit ScopedGraphicsContext(Window& window);
103
104 /** Overloaded constructor, gives back context to its transient parent when done */
105 explicit ScopedGraphicsContext(Window& window, Window& transientParentWindow);
106
107 /** Destructor for clearing current context, if not done yet */
108 ~ScopedGraphicsContext();
109
110 /** Early context clearing, useful for standalone windows not created by you. */
111 void done();
112
113 /** Get a valid context back again. */
114 void reinit();
115
116 DAF_DECLARE_NON_COPYABLE(ScopedGraphicsContext)
117 DAF_PREVENT_HEAP_ALLOCATION
118
119 private:
120 Window& window;
121 Window::PrivateData* const ppData;
122 bool active;
123 bool reenter;
124 };

359 /**
360 A drag of files from another application over this window, see setAcceptingFileDrops().
361 Valid during the call it is passed to.

363 struct FileDropEvent {
364 /** Pointer position, in the coordinates the window's top-level widgets get mouse events in. */

410 /**
411 Add a callback function to be triggered on every idle cycle or on a specific timer frequency.
412 You can add more than one, and remove them at anytime with removeIdleCallback().
413 This can be used to perform some action at a regular interval with relatively low frequency.
414
415 If providing a timer frequency, there are a few things to note:
416 1. There is a platform-specific limit to the number of supported timers, and overhead associated with each,
417 so you should create only a few timers and perform several tasks in one if necessary.
418 2. This timer frequency is not guaranteed to have a resolution better than 10ms
419 (the maximum timer resolution on Windows) and may be rounded up if it is too short.
420 On X11 and MacOS, a resolution of about 1ms can usually be relied on.
421
422 The callback is not owned or tracked beyond this, so it MUST be removed with removeIdleCallback()
423 before the callback object is destroyed, and while this window still exists.
424 A callback without a timer frequency is registered on the Application rather than on this window,
425 and destroying the window does not remove it, so a forgotten one is called through a dangling pointer.
426 */
427 bool addIdleCallback(IdleCallback* callback, uint timerFrequencyInMs = 0);
